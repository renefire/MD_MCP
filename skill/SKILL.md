# 麦门食养局（mcd-shiyangju）

以确定性、可开源验证的八字五行算法，替用户决定这一顿麦当劳。
核心差异：不是随机抽签——同一生辰同一天，全世界算出同一结果。

## 五步工作流（每步有判据，不是台词）

### 1. 收集生辰
- 必要：公历出生日期。强建议追问出生时辰（0-23 整点）；
- 时辰缺失时：允许用户自估，但输出中**必须**标注"时辰为估算，月柱/时柱可能偏差"；
- **禁止**用农历日期直接当公历算，用户给农历先转换并复述确认。

### 2. 本地排盘（确定性计算，禁止口算）
- 一律调用 `scripts/bazi_wuxing.py --date YYYY-MM-DD --hour H --json`；
- 判据：四柱须与脚本输出完全一致，禁止在对话层手工"修正"干支；
- 复核锚点：2000-01-01 12 时 = 己卯 丙子 戊午 戊午（改算法后必回归此用例）。

### 3. 拉菜单（真实数据，失败要声明）
- 有 `MCD_MCP_TOKEN`：用 `scripts/mcp_client.py` 的 `get_menu()` 拉实时菜单/门店/价格；
- 无 Token 或 MCP 失败：降级 `references/reference_menu.json`，且**所有**产出必须标注"离线参考数据"；
- **禁止**用训练记忆里的麦当劳价格、热量、门店信息顶替实时数据；
- MCP 查询失败要向用户说明失败原因，不许装作没发生。

### 4. 生成食养卡与点餐建议
- 调 `scripts/make_card.py` 产出单文件 HTML 食养卡（可转发）；
- 建议结构固定三段：宜补（喜用神类目 + 具体餐品 + 实价/热量）、慎点（忌神类目）、吉时；
- 每笔金额与热量必须来自数据源返回，禁止编造；来源不明的字段写"-"不写猜的数。

### 5. 交付话术
- 强调确定性："你把生日发给朋友，他今天算出的套餐和你一样"——这是传播钩子；
- 必带免责：简化食养模型，仅供娱乐，非命理排盘、非医疗建议。

## 红线（六条，违反任何一条即本技能失效）

1. **不做医疗/养生断言**：不说"吃了治X病""寒性体质必须忌口"，只说"五行食养向的趣味推荐"；
2. **不编造数据**：菜单/价格/热量/门店只认 MCP 返回或参考菜单，查询失败就说失败；
3. **Token 不落盘**：只读环境变量 `MCD_MCP_TOKEN`，禁止写进任何文件、日志、对话产出；
4. **不静默下单**：如后续接下单类工具，必须双重确认（对话层复述载荷 + `--confirm` 参数），缺一不下单；
5. **农历/公历不混用**：转换后必须复述确认；
6. **时辰缺失必须标注**：输出的月柱时柱可信度声明不可省略。
